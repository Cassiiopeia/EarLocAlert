## 1. 배경과 목적

### 1.1 해결하려는 상황

- 이동 중 졸다가 내려야 할 곳을 지나친다
- 도서관·사무실 같은 조용한 곳에서 알람이 울려 민망하다
- 이어폰을 끼고 있는데 알림이 **스피커로** 나가 당황한다

### 1.2 목적

**특정 위치에 도착하거나 떠날 때, 주변을 방해하지 않으면서 확실하게 알린다.**

두 조건을 동시에 만족해야 의미가 있다. 조용하기만 하고 못 깨우면 실패고, 확실하지만 시끄러우면 기존 알람 앱과 같다.

### 1.3 장소는 사용자가 정한다 — 특정 용도를 전제하지 않는다

**"셔틀버스에서 회사 도착"은 여러 사용 사례 중 하나일 뿐이다.** 설계·문구·화면 어디에서도 특정 용도를 전제하지 않는다.

| 사용 사례 | 등록 형태 |
|---|---|
| 대중교통·셔틀에서 하차 지점 | 진입 알림 |
| 카풀 동승자 하차 지점 | 진입 알림 |
| 아이 하원·학원 도착 확인 | 진입 알림 |
| 병원·관공서 등 처음 가보는 곳 | 진입 알림 |
| 약속 장소 도착 | 진입 알림 |
| 집을 나설 때 리마인더 (가스·창문) | **이탈 알림** |
| 사무실을 벗어날 때 할 일 알림 | **이탈 알림** |
| 자주 가는 곳 여러 개 동시 운영 | 양방향 + 개별 on/off |

그래서 기능은 **"장소 하나를 등록하고 방향을 고르는 것"** 이라는 하나의 추상으로만 존재한다. "출근 모드" 같은 용도별 기능을 만들지 않는다.

문구도 마찬가지다. 예시를 들 때 회사·집만 쓰지 않고, 화면 안내에 "출근"·"통근" 같은 단어를 쓰지 않는다.

**등록 개수가 늘어나면 관리 기능이 필요해진다** — 즐겨찾기·정렬·그룹 같은 것들이다. MVP 에는 넣지 않고 [11-ROADMAP](11-ROADMAP.md) Phase 2 에서 다룬다.

### 1.4 이 앱의 성격

일반 알람 앱·지도 앱과의 차이는 다음과 같다.

| 기능 | EarLocAlert | 일반 알람 앱 | 지도 앱 |
|---|---|---|---|
| 위치 기반 발화 | O | X | 일부 |
| 백그라운드 동작 | O | O | X |
| 이어폰(줄·블루투스) 자동 감지 | O | X | X |
| 스피커 출력 차단 | O | X | X |
| 이탈(떠날 때) 알림 | O | X | X |

핵심은 세 번째와 네 번째다. **이어폰이 연결돼 있으면 이어폰으로만, 아니면 진동만.** 이 동작이 이 앱의 존재 이유다.

### 1.5 사용자가 앱을 열지 않는다는 사실

이 앱은 **위치를 한 번 등록하면 그 뒤로 열리지 않는다.** 설계·수익·품질 판단 전반에 이 사실이 걸린다.

- 알림이 울리는 순간이 사용자와 만나는 **거의 유일한 접점**이다
- 그래서 그 순간이 완벽해야 한다. 여기서 실패하면 앱을 지운다
- 그리고 광고를 띄울 수 있는 지점도 사실상 거기뿐이다 (F8)

## 2. 개발 범위

### 2.1 MVP — 1차 스토어 출시분

**목표는 "기능 4개 완성"이 아니라 "스토어에 올라가 실제로 광고가 나가는 상태"다.**

| 구분 | 항목 |
|---|---|
| 기능 | F1 위치 등록 · F2 지오펜싱 · F3 알림 · F4 지도 표시 · F8 광고 |
| 설정 | F6 중 알림 간격 · 진동 강도만 |
| 출시 필수 | 앱 아이콘 · 스플래시 · 개인정보 처리방침 URL · 스토어 등록정보 · 백그라운드 위치 시연 영상 · 데이터 보안 양식 |

출시 필수 항목은 기능 개발과 **같은 비중으로 다룬다.** 코드가 완성되고도 여기서 막혀 못 올리는 경우가 실제로 많다 → [09-RELEASE](09-RELEASE.md)

### 2.2 Phase 2 이후

F5 다국어 · F7 알림 이력 · F1.2 주소 검색 · F6 나머지 설정 → [11-ROADMAP](11-ROADMAP.md)

### 2.3 만들지 않는 것

| 제외 | 이유 |
|---|---|
| 회원가입 · 로그인 | 저장할 것이 위치 몇 개뿐이다. 계정은 심사 리스크만 늘린다 |
| 서버 · 기기 간 동기화 | 위치를 서버로 보내는 순간 개인정보 심사 난이도가 다른 차원이 된다 |
| 경로 안내 · 내비게이션 | 지도 앱의 영역이다 |
| 위젯 · 워치 앱 | 1차 출시 후 판단 |

## 3. 기능 요구사항

### F1. 위치 등록 및 관리

| 번호 | 요구사항 | 단계 |
|---|---|---|
| F1.1 | 지도에서 직접 위치 선택 | MVP |
| F1.2 | 주소·상호 검색으로 위치 찾기 | Phase 2 |
| F1.3 | 위치별 이름 지정 (예: "학원", "약속 장소", "환승역") | MVP |
| F1.4 | 알림 반경 설정 (50m ~ 2km) | MVP |
| F1.5 | 알림 유형 선택 — 진입 / 이탈 / 양방향 | MVP |
| F1.6 | 등록된 위치 편집 · 삭제 | MVP |
| F1.7 | 위치별 활성 / 비활성 토글 | MVP |
| F1.8 | **위치별 알림 시간대 (요일 + 시각 구간, 여러 개)** | MVP |

**F1.7 은 원 명세에 없으나 추가한다.** 삭제 없이 잠시 끄는 수단이 없으면 사용자가 위치를 지웠다 다시 등록한다.

**F1.8 도 원 명세에 없으나 추가한다** ([이슈 #81](https://github.com/Cassiiopeia/EarLocAlert/issues/81)). 회사 근처에 살거나 자주 지나는 곳을 등록하면 하루에도 몇 번씩 무의미하게 울린다. 사용자가 원하는 것은 "그곳에 도착하면"이 아니라 **"출근길에 그곳에 도착하면"** 이다.

- 시간대를 하나도 두지 않으면 **항상 알림**이다 — 기존 동작 그대로다
- 여러 개를 두면 OR 이며, 자정을 넘기는 구간(예: 23:00~02:00)도 지원한다
- **창 안에서 일어난 진입/이탈만** 알린다. 창이 열릴 때 이미 반경 안에 있어도 울리지 않는다

특정 용도를 전제하지 않는다는 1.3 원칙은 그대로다 — "출근 모드"가 아니라 **"시간대"** 라는 하나의 추상이고, 야간 근무·주말 학원·평일 병원 어디에나 같은 방식으로 쓴다.

**등록 개수 상한은 iOS 제약을 따른다** — [05-PLATFORM](05-PLATFORM.md) 참조. 상한에 도달하면 새 등록을 막고 이유를 화면에 표시한다.

### F2. 지오펜싱

| 번호 | 요구사항 | 단계 |
|---|---|---|
| F2.1 | 앱이 화면에 없어도 위치 모니터링 | MVP |
| F2.2 | 설정 반경 진입 감지 | MVP |
| F2.3 | 설정 반경 이탈 감지 | MVP |
| F2.4 | 위치 갱신 주기는 플랫폼 능력에 맞춰 조정 | MVP |

**F2.4 의 "3초 주기"는 Android 에만 적용한다.** iOS 는 앱이 백그라운드일 때 초 단위 폴링을 허용하지 않는다. 플랫폼별 실제 동작은 [05-PLATFORM](05-PLATFORM.md) 에 있다.

**같은 진입에 대해 알림은 한 번만 발생한다.** 반경 경계에서 GPS 가 흔들리면 진입/이탈이 반복 판정되어 알림이 연속으로 터진다. 판정 규칙은 [03-DOMAIN](03-DOMAIN.md) 에 있다.

### F3. 알림 시스템

이 앱의 핵심이다. 다른 기능이 완벽해도 여기가 실패하면 앱이 무의미하다.

| 번호 | 요구사항 | 단계 |
|---|---|---|
| F3.1 | 진동 알림 — 설정 간격으로 반복 | MVP |
| F3.2 | 알림 화면 표시 | MVP |
| F3.3 | 이어폰(줄·USB-C·블루투스) 연결 여부 자동 감지 | MVP |
| F3.4 | 이어폰 연결 시 → **이어폰으로만** 소리 재생 | MVP |
| F3.5 | 이어폰 미연결 시 → **진동만.** 소리 없음 | MVP |
| F3.6 | 사용자가 직접 끌 때까지 지속 | MVP |
| F3.7 | 어떤 경우에도 기기 스피커로 소리를 내지 않는다 | MVP |

**F3.7 은 이 앱의 계약이다.** 도서관에서 스피커가 한 번 울리면 사용자는 앱을 지운다. 구현이 불확실하면 소리를 포기하고 진동만 한다 — 스피커 출력 위험을 감수하지 않는다.

**F3.2 의 화면 형태는 플랫폼마다 다르다.** Android 는 조건이 맞으면 전체화면, iOS 는 일반 알림이다 → [05-PLATFORM](05-PLATFORM.md)

**F3.6 은 광고보다 우선한다.** 해제 버튼은 광고 로딩 상태와 무관하게 항상 즉시 동작한다 → [02-ARCHITECTURE](02-ARCHITECTURE.md)

### F4. 지도 시각화

| 번호 | 요구사항 | 단계 |
|---|---|---|
| F4.1 | 등록된 모든 위치를 지도에 표시 | MVP |
| F4.2 | 알림 반경을 원으로 표시 | MVP |
| F4.3 | 현재 내 위치 표시 | MVP |
| F4.4 | 알림 유형별 색상 구분 (진입/이탈/양방향) | MVP |

**F4.5 가 중요하다.** 백그라운드 앱은 "지금 감시 중인지" 사용자가 알 방법이 없다. 이게 안 보이면 앱을 믿지 못하고, 믿지 못하면 쓰지 않는다.

### F8. 광고 — 신설

원 명세에 없던 요구사항이다. **1차 출시부터 포함한다** — 나중에 넣으면 재심사에 개인정보 문서 전면 수정이 따라온다 ([10-DECISIONS](10-DECISIONS.md)).

| 번호 | 요구사항 | 단계 |
|---|---|---|
| F8.1 | 알림 해제 버튼을 누른 **다음 화면**에 전면광고 | MVP |
| F8.2 | 위치 목록 · 설정 화면 하단 배너 | MVP |
| F8.3 | 전면광고 최소 노출 간격 3분 | MVP |
| F8.4 | 전면광고 1일 노출 상한 | MVP |
| F8.5 | 광고 동의 수집 (UMP) | MVP |
| F8.6 | 개발 빌드는 테스트 광고 ID 고정 | MVP |

**금지 사항이 요구사항만큼 중요하다.**

| 금지 | 이유 |
|---|---|
| 알림 화면 **위에** 광고를 겹치는 것 | 우발적 클릭 유도 = AdMob 계정 정지 |
| 광고 로딩을 기다리느라 해제를 지연시키는 것 | F3.6 위반. 별점 1점의 지름길 |
| 앱 시작 직후·조작 중 전면광고 | "예기치 않은 광고" 정책 위반 |
| 알림이 연속 발생할 때 매번 전면광고 | F8.3 으로 차단한다 |

## 4. 비기능 요구사항

### 4.1 성능

| 항목 | 목표 |
|---|---|
| 진입 감지 → 알림 발화 (Android) | 5초 이내 |
| 진입 감지 → 알림 발화 (iOS) | OS 가 전달하는 시점에 즉시. 지연은 OS 재량 |
| 앱 콜드 스타트 | 3초 이내 |
| 배터리 소모 | **실측 후 확정.** 측정 전에 수치를 약속하지 않는다 |

원 명세의 "하루 15% 미만"은 3초 폴링과 양립하지 않는다. 둘 다 적으면 둘 중 하나가 거짓말이 된다 → [10-DECISIONS](10-DECISIONS.md)

### 4.2 안정성

| 항목 | 목표 |
|---|---|
| 백그라운드 서비스 생존 | 기기 재부팅 후 자동 복구 |
| 알림 해제 동작 | **100%.** 광고·네트워크·오디오 실패와 무관하게 항상 동작 |
| 크래시율 | 0.5% 미만 (스토어 기준 미달 시 노출 불이익) |

### 4.3 개인정보

| 항목 | 내용 |

## 5. 인수 조건

MVP 완료 판정 기준이다. **실기기에서 확인한다.** 시뮬레이터·에뮬레이터 결과는 인정하지 않는다 — 백그라운드 동작과 오디오 라우팅은 그곳에서 실제와 다르게 동작한다.

| 번호 | 조건 |
|---|---|
| A-01 | 지도에서 위치를 찍고 이름·반경·알림 유형을 지정해 저장할 수 있다 |
| A-02 | 저장한 위치가 지도에 반경 원과 함께 표시된다 |
| A-03 | 앱을 화면에서 내린 상태로 반경에 진입하면 알림이 발생한다 (Android: 5초 이내) |
| A-04 | 이탈 알림으로 설정한 위치에서 반경을 벗어나면 알림이 발생한다 |
| A-05 | **이어폰(줄·USB-C·블루투스) 연결 상태**에서 알림이 발생하면 소리가 이어폰으로만 나간다 |
| A-06 | **이어폰 미연결 상태**에서 알림이 발생하면 진동만 발생하고 스피커는 무음이다 |
| A-07 | 알림은 사용자가 해제할 때까지 설정 간격으로 계속 진동한다 |
| A-08 | 해제 버튼을 누르면 즉시 알림이 멈춘다 — 광고 로딩 중이어도 동일하다 |
| A-09 | 해제 후 전면광고가 노출되며, 3분 이내 재발생 시에는 노출되지 않는다 |
| A-10 | 기기를 재부팅해도 모니터링이 자동 복구된다 |
| A-11 | 반경 경계에서 GPS 가 흔들려도 알림이 중복 발생하지 않는다 |
| A-12 | 권한을 거부한 상태에서 앱이 죽지 않고, 무엇이 필요한지 화면에 설명한다 |
| A-13 | 최초 실행 시 광고 동의(UMP) 화면이 표시된다 |
| A-14 | Play Console · App Store Connect 심사에 제출 가능한 상태다 (09-RELEASE 체크리스트 전항 충족) |

**A-05 와 A-06 이 이 앱의 인수 조건 중 가장 중요하다.** 나머지를 다 만족해도 이 둘이 실패하면 출시하지 않는다.
