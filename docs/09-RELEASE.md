# 09. 출시 · 심사 대응

**이 프로젝트에서 가장 과소평가되기 쉬운 영역이다.**

코드가 완성되어도 여기서 막히면 앱이 세상에 나가지 못한다. 그리고 이 앱은 하필 **심사에서 가장 까다로운 두 가지**를 동시에 가지고 있다 — 백그라운드 위치와 광고.

## 심사 리스크 순위

| 순위 | 항목 | 왜 위험한가 |
|---|---|---|
| 1 | **백그라운드 위치 권한** | Play 는 별도 선언 양식 + 시연 영상을 요구한다. 반려가 잦고 재심사에 시간이 걸린다 |
| 2 | **개인정보 처리방침 정확성** | 위치는 전송 안 하는데 광고 식별자는 전송한다. 이 구분을 틀리면 허위 신고가 된다 |
| 3 | iOS 백그라운드 위치 사유 | Apple 은 "정말 백그라운드가 필요한가"를 본다 |
| 4 | iOS Privacy Manifest | 누락 시 업로드 단계에서 거부된다 |
| 5 | 광고 정책 | 배치가 잘못되면 심사보다 AdMob 계정 정지가 먼저 온다 |

**1번을 위해 준비하는 자료가 곧 앱의 설명 자료가 된다.** 미루지 말고 개발과 병행한다.

## 백그라운드 위치 — 최대 관문

### 왜 이 앱이 백그라운드 위치를 필요로 하는가

심사에 제출할 논거다. 문서에 확정해두고 양쪽 스토어에 같은 논리로 답한다.

> 이 앱의 목적은 **사용자가 앱을 보고 있지 않을 때 목적지 도착을 알리는 것**이다.
> 셔틀버스에서 졸고 있거나, 화면을 끄고 이동 중인 사용자가 주 대상이다.
> 앱이 화면에 떠 있을 때만 동작한다면 사용자는 계속 화면을 보고 있어야 하고,
> 그러면 알림 자체가 불필요해진다. **백그라운드 동작 없이는 앱의 기능이 성립하지 않는다.**

이 논거의 강점은 **사실이라는 것**이다. 억지로 만든 명분이 아니다.

### 시연 영상에 담아야 할 것

Play 권한 선언에 첨부한다.

1. 앱에서 위치를 등록하는 화면
2. **앱을 완전히 닫는 장면** (최근 앱에서 제거)
3. 해당 위치로 이동
4. 알림이 발생하는 장면
5. 알림을 해제하는 장면

"앱을 닫았는데도 알림이 온다"는 것이 백그라운드 권한이 필요한 이유 그 자체다. 영상이 그걸 보여주면 된다.

### 권한 요청 화면이 심사 자료다

[06-UX](06-UX.md) 의 권한 온보딩 화면 — "앱을 열지 않아도 도착을 알려드리려면 필요합니다" — 을 스크린샷으로 제출한다. **앱이 사용자에게 이유를 설명하고 있다는 증거**가 심사에서 유리하게 작용한다.

## 신뢰성 권한 사유서 (#74)

백그라운드 위치 다음으로 설명이 필요한 항목들이다. 셋 다 **거부돼도 앱이 동작한다**는 점을 함께 밝힌다 — 필수가 아니라는 사실이 심사에서 가장 유리한 논거다.

| 항목 | 심사에 제출할 논거 |
|---|---|
| `FOREGROUND_SERVICE_LOCATION` | 등록한 장소의 진입·이탈을 앱이 닫힌 상태에서 감시한다. 감시 대상이 0건이면 서비스를 내린다. 상시 알림으로 감시 중임을 사용자에게 계속 보여준다 |
| `SYSTEM_ALERT_WINDOW` | 도착 알림은 **놓치면 목적을 잃는** 알림이다(내릴 정류장). 사용자가 다른 앱을 쓰는 중에도 알림 화면을 띄우기 위해 사용한다. 광고·과금 UI 를 띄우는 데 쓰지 않는다 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 절전 모드가 지오펜스 콜백을 지연시키면 도착 후에 알리게 되어 기능이 무의미해진다. 온보딩에서 이유를 설명하고 한 번만 요청하며, 거절해도 앱을 계속 쓸 수 있다 |

**시연 영상에 한 장면 더 넣는다** — 영상을 재생 중인 화면 위로 알림 화면이 뜨는 장면. `SYSTEM_ALERT_WINDOW` 가 무엇에 쓰이는지 한 번에 보여준다.

**하면 안 되는 것** — 이 권한들을 필수처럼 요구하거나, 거부 시 앱 진입을 막는 것. 심사 반려 사유이자 [10-DECISIONS](10-DECISIONS.md) 006 위반이다.

### `REQUEST_INSTALL_PACKAGES` 는 스토어 배포 전에 걷어낸다 (#104, #109)

**빼는 방법은 CI Secret `ENV_FILE` 에서 `DEV_FLAG` 줄을 지우는 것 하나다.** 코드를 건드리지 않는다 — gradle 이 그 값으로 매니페스트 병합을 바꾼다.

```
ENV_FILE 에 DEV_FLAG=true 있음  →  설치 권한 선언됨 · 인앱 업데이트 있음 · 테스트 광고
ENV_FILE 에 DEV_FLAG 없음       →  설치 권한 빠짐 · 인앱 업데이트 없음 · 실제 광고
```

**실제로 한 번 놓쳤다** (2026-08-21). 실기기 검증 편의를 위해 `DEV_FLAG=true` 를 CI Secret 에 넣어두었는데, **같은 빌드가 Play 에 올라가면서** 심사용 AAB 에도 설치 권한이 들어갔다. Play Console 이 `REQUEST_INSTALL_PACKAGES` 선언을 요구하는 것으로 드러났다.

검증 빌드와 심사 빌드가 같은 Secret 을 쓰므로 **둘을 동시에 만족시킬 수 없다.** Play 트랙에 올리기 시작하면 테스터가 Play 에서 자동 업데이트를 받으므로 사이드로드용 자체 업데이트가 필요 없어진다 — 그 시점에 빼는 것이 맞다.

**빼고 나면 반드시 확인한다:**

```
aapt2 dump badging <apk> | grep -c REQUEST_INSTALL_PACKAGES   # 0 이어야 한다
```


인앱 업데이트([10-DECISIONS](10-DECISIONS.md) 027)를 위해 선언했다. **스토어 배포에는 필요 없고, Play 는 이 권한을 특히 까다롭게 본다.**

스토어 배포 준비 시 함께 제거할 것:

- `AndroidManifest.xml` 의 `REQUEST_INSTALL_PACKAGES` 권한과 `FileProvider` 선언
- `ApkInstaller.kt` · `app_installer` 채널
- `lib/features/update/` 전체와 설정 화면의 업데이트 항목
- `res/xml/file_paths.xml`

**남겨두고 심사에 올리지 않는다.** 사유서로 통과시킬 수 있는 항목이 아니고, 스토어에서 받는 앱에 자체 업데이트 경로가 있을 이유도 없다.

## 개인정보 처리방침

### 반드시 구분해서 쓴다

| 데이터 | 실제 동작 | 처리방침 표기 |
|---|---|---|
| 위치 | 기기 내부에서만 처리·저장. **외부 전송 없음** | 수집하지만 전송하지 않음 |
| 광고 식별자 | **AdMob SDK 가 외부로 전송** | 광고 목적 수집·공유 |
| 알림 이력 | 기기 내부 저장 | 전송 없음 |
| 계정 정보 | 없음 (회원가입 없음) | 수집 안 함 |

**"어떤 정보도 외부로 전송하지 않습니다"라고 쓰면 허위다.** 광고 SDK 가 전송한다. 원 명세([이슈 #1](https://github.com/Cassiiopeia/EarLocAlert/issues/1))에 그렇게 적혀 있지만 광고를 넣기로 한 이상 사실이 아니다.

반대로 "위치 정보를 수집합니다"라고만 쓰면 사용자가 서버로 보낸다고 오해한다. **위치는 기기 밖으로 나가지 않는다는 점을 명시적으로 쓴다** — 이건 이 앱의 강점이기도 하다.

### 호스팅

URL 이 필요하다. GitHub Pages 로 충분하다. 앱 안에서도 열 수 있어야 한다 (설정 화면).

한국어·영어 둘 다 준비한다. 스토어를 글로벌로 열면 영어 버전을 요구받는다.

### 데이터 보안 양식 작성 기준

Play 에서 말하는 "수집"은 **데이터가 기기 밖으로 나가는 것**을 뜻한다. 기기 안에서만 처리하면 수집이 아니다.

| 데이터 유형 | 수집 | 공유 | 비고 |
|---|---|---|---|
| 위치 (대략·정확) | 아니오 | 아니오 | 기기 내부 처리만 |
| 광고 ID | 예 | 예 | AdMob |
| 앱 활동·진단 | **AdMob SDK 의 실제 수집 항목을 확인해 반영한다** | | 확인 필요 |

**마지막 줄을 추정으로 채우지 않는다.** Google 이 공개하는 AdMob SDK 데이터 수집 목록을 보고 그대로 옮긴다. 틀리게 신고하면 나중에 앱이 정지된다.

### 용도 설명 문구를 대충 쓰지 않는다

```
X  "위치 정보가 필요합니다"
X  "앱 기능을 위해 위치를 사용합니다"

O  "앱을 열지 않아도 등록한 장소에 도착·출발할 때 알려드리기 위해
   백그라운드에서도 위치를 확인합니다. 위치 정보는 기기에만 저장되며
   외부로 전송되지 않습니다."
```

**이 문구는 심사자가 읽는다.** 그리고 사용자가 권한 다이얼로그에서도 읽는다. 두 목적을 동시에 만족해야 한다.

### ATT 를 넣을지 결정한다

| 선택 | 결과 |
|---|---|
| ATT 요청함 | 개인 맞춤 광고 가능 → 수익 유리. 다이얼로그가 하나 늘어난다 |
| ATT 요청 안 함 | 비개인 맞춤 광고만 → 수익 하락. 심사 항목 하나 감소 |

**권한 요청이 이미 세 개(위치·항상 위치·알림)라는 점을 고려한다.** 여기에 추적 동의까지 붙으면 온보딩에서 이탈이 늘어난다. → [10-DECISIONS](10-DECISIONS.md)
