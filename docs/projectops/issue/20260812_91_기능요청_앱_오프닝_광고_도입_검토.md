📝 현재 문제점
---

현재 이 앱의 광고는 **알림 해제 직후 뜨는 전면광고 한 종류**뿐이다 (#59). 다른 앱에서 흔히 보이는 "앱을 켜자마자 화면을 덮는 광고"와 "앱을 쓰다가 화면 전환 때 끼어드는 광고"가 각각 무엇이고 이 앱에 맞는지가 정리되어 있지 않다.

먼저 용어를 정리한다. 둘 다 **AdMob 안에 있는 형식**이고 별도 광고 네트워크가 아니다.

| 본 것 | 형식 이름 | 언제 뜨는가 | 현재 상태 |
|---|---|---|---|
| 앱 켜면 바로 뜨는 전체화면 광고 | **앱 오프닝 (App Open)** | 앱 실행, 백그라운드에서 복귀할 때 | 미구현 |
| 쓰다가 화면 넘어갈 때 뜨는 전체화면 광고 | **전면 (Interstitial)** | 화면 전환 시점 | 구현됨, 알림 해제 후에만 |
| 화면 가장자리에 붙어 있는 띠 | 배너 | 상시 | 미도입 |
| 보고 나면 보상 주는 것 | 보상형 | 사용자가 선택 | 해당 없음 |

즉 "앱 켜면 빡 뜨는 것"은 앱 오프닝 광고이고, "서핑하다 뜨는 것"은 전면광고다. 이 앱은 후자만 있고, 그것도 알림 해제 직후 한 지점에만 있다.

**이 앱에서 앱 오프닝 광고는 다른 앱보다 훨씬 위험하다.**

이 앱은 알림이 울리면 백그라운드에서 앱을 전면으로 승격시킨다. 앱 오프닝 광고는 정의상 **앱이 포그라운드로 올라오는 그 순간**에 뜨므로, 아무 조건 없이 붙이면 다음이 벌어진다.

1. 도착 알림이 울린다. 진동이 시작된다
2. 앱이 전면으로 올라온다
3. **알림 화면 대신 광고가 뜬다**
4. 진동은 계속 울리는데, 끄려면 광고를 먼저 닫아야 한다

이건 "광고를 기다렸다가 알림을 해제하지 않는다"는 이 프로젝트의 핵심 규칙(`docs/02-ARCHITECTURE.md` 규칙 4)을 정면으로 위반한다. 버스에서 급하게 껐는데 진동이 몇 초 더 계속되면 사용자는 앱을 지운다. 해제 버튼 근처에서 우발적 클릭을 유도하는 형태가 되면 **AdMob 계정 정지 사유**이기도 하다 (`docs/07-MONETIZATION.md`).

🛠️ 해결 방안 / 제안 기능
---

**결론부터: 도입은 가능하되 진입 경로를 구분해야 한다.**

앱이 전면으로 올라오는 이유는 두 가지이고, 이 둘을 절대 같이 취급하면 안 된다.

| 진입 경로 | 앱 오프닝 광고 |
|---|---|
| 사용자가 아이콘을 눌러 직접 실행 | 노출 가능 |
| 사용자가 앱 전환으로 되돌아옴 | 노출 가능 |
| **알림 때문에 승격됨** | **절대 노출 금지** |
| **대기 중인 알림이 남아 있는 상태** | **절대 노출 금지** |

판정 기준은 이미 앱 안에 있다. 백그라운드 알림을 포그라운드 세션으로 잇는 지점(`lib/app/pending_alert_launcher.dart`)이 "지금 처리할 알림이 있는가"를 알고 있으므로, 그 값이 참이면 광고를 아예 요청하지 않는다.

추가로 지켜야 할 것

- **알림이 울리는 중에는 어떤 광고도 뜨지 않는다.** 앱 오프닝이든 전면이든 동일하다
- 앱 오프닝 광고는 **로딩을 기다리지 않는다.** 준비되어 있지 않으면 그냥 건너뛰고 홈을 보여준다
- 빈도 제어를 전면광고와 **함께** 센다. 따로 세면 알림 한 번에 광고를 두 번 보는 흐름이 생긴다 (`lib/features/ads/domain/ad_frequency_policy.dart`)
- 콜드 스타트 첫 화면은 권한 온보딩이다. **온보딩 위에는 광고를 띄우지 않는다** — 권한 설명 흐름에 광고가 끼면 사용자가 권한을 전부 거부한다 (`docs/07-MONETIZATION.md`)

**도입 여부는 수익과 이탈의 교환이다.** 앱 오프닝 광고는 노출 기회가 많아 수익이 크게 늘지만, 이 앱은 실행 빈도가 높고 한 번 실행에 머무는 시간이 짧다. 장소 하나 확인하러 열었는데 매번 전체화면 광고를 닫아야 하면 체감이 나쁘다. **실행마다가 아니라 하루 몇 회 상한을 두는 쪽**을 먼저 검토한다.

⚙️ 작업 내용
---

- 앱 오프닝 광고 서비스 추가 (`lib/features/ads/`), 인터페이스 뒤에 두어 테스트 가능하게 유지
- 진입 경로 판정: 알림 승격 및 대기 알림 존재 시 광고 요청 자체를 차단
- 빈도 정책을 전면광고와 통합, 하루 상한 도입 검토
- 온보딩 화면 노출 제외
- 광고 단위 ID 를 빌드 종류로 분기 (`lib/features/ads/domain/ad_unit_ids.dart` 방식 그대로 확장, 디버그는 테스트 ID 고정)
- 차단 조건 테스트: 알림 승격 경로에서 광고가 요청되지 않는지 검증
- `docs/07-MONETIZATION.md` 광고 형식 표 갱신, `docs/10-DECISIONS.md` 에 결정 항목 추가

**선행 조건 (사용자 작업)**

현재 AdMob 앱이 등록되어 있지 않아 테스트 광고 ID 로만 동작한다. 아래가 끝나야 실제 송출이 가능하다.

1. AdMob 콘솔에서 앱 등록 (Android, iOS 각각)
2. 앱 오프닝 광고 단위 생성, 발급된 ID 를 빌드 시크릿에 등록
3. `app-ads.txt` 를 개인정보 처리방침과 같은 도메인에 게시
4. UMP 동의 흐름 확인, iOS 는 ATT 포함 여부 결정 (`docs/09-RELEASE.md` 미결 항목)
