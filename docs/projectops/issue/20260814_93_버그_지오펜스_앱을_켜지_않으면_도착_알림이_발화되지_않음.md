🗒️ 설명
---

**앱을 실행하지 않으면 등록한 장소에 도착해도 알림이 발화되지 않는다.** 도착한 뒤 앱을 켜는 순간에야 진동과 알림 화면이 뜬다.

이 앱의 존재 이유가 "앱을 켜지 않아도 도착을 알려주는 것"이므로 핵심 가치가 성립하지 않는 상태다.

실기기에서 확인된 사실은 다음과 같다.

| 확인 항목 | 결과 |
|---|---|
| 감시 서비스(`AlertWatchService`) 생존 | **살아있음** (상시 알림 표시 중) |
| 배터리 최적화 예외 | **허용됨** ("제한 없음") |
| 도착 시점 알림 발생 | **없음** (알림도 진동도 없음) |
| 앱 실행 직후 | **즉시 발화** |

감시 서비스가 살아있고 절전 예외도 받은 상태에서 발화가 없었다. 즉 **발화 주체의 문제가 아니라 이벤트가 도달하지 않는 문제**다.

### 원인

`native_geofence` 1.2.1 의 Android 이벤트 전달 경로가 WorkManager 를 경유한다.

```
OS 감지 → 플러그인 브로드캐스트 리시버 (즉시 도착)
        → WorkManager 큐에 적재하고 리시버 종료   ← 여기서 끊긴다
        → 백그라운드 워커
        → FlutterEngine 신규 부팅
        → 앱 콜백
```

브로드캐스트 자체는 즉시 온다. 그런데 리시버가 그 자리에서 아무것도 하지 않고 WorkManager 에 작업만 넣는다. 그 적재 방식에 두 가지 결함이 있다.

**첫째, 즉시 실행이 보장되지 않는다.** 즉시 실행 쿼터가 소진되면 일반 작업으로 강등되며, 강등된 작업은 Doze 와 앱 대기 버킷 제한을 그대로 받아 수 분에서 수십 분 지연된다. 쿼터는 앱 사용 빈도로 결정되므로 **앱을 쓰지 않을수록 알림이 오지 않는다** — 이 앱의 사용 패턴과 정확히 반대다.

**둘째, 한 번 실패하면 이후 전부 실패한다.** 작업을 기존 체인에 이어붙이는 방식(`APPEND`)을 쓰는데, 선행 작업이 실패 또는 취소 상태면 뒤에 붙는 작업도 같은 상태가 되어 실행되지 않는다. 그리고 해당 워커에는 실패로 끝나는 경로가 세 곳 있다 (콜백 핸들 없음, 콜백 정보 조회 실패, 엔진 null).

**구조적 결함은 실패 가능한 엔진 부팅을 이벤트마다 반복한다는 점이다.**

### 앱을 켜면 울리는 이유

앱이 뜰 때마다 지오펜스를 전부 재등록하고, 등록 옵션에 "등록 시점에 이미 반경 안이면 즉시 진입 이벤트 발생"이 켜져 있다. 앱이 포그라운드라 이번엔 워커가 곧바로 실행되어 그제서야 판정이 돈다.

**즉 사용자가 겪은 것은 도착해서 울린 것이 아니라 앱을 켜서 재등록되며 울린 것이다. 실제 도착 이벤트는 유실됐다.**

### 관련 파일

- `lib/features/geofence/data/native_geofence_monitor.dart`
- `lib/app/background/geofence_callback.dart`
- `lib/app/geofence_registration_sync.dart`
- `android/app/src/main/kotlin/kr/suhsaechan/ear_loc_alert/AlertWatchService.kt`
- `android/app/src/main/kotlin/kr/suhsaechan/ear_loc_alert/MainActivity.kt`
- `android/app/src/main/AndroidManifest.xml`

### 함께 발견된 문제

`AndroidManifest.xml` 에 재부팅 감지 권한(`RECEIVE_BOOT_COMPLETED`)과 "재부팅 후 감시 복구" 주석이 있으나 **해당 리시버가 존재하지 않는다.** 플러그인 리시버는 지오펜스 등록만 되살리고 감시 서비스는 켜지 않는다. 재부팅 후 앱을 실행하지 않으면 감시 서비스가 죽은 채로 남는다.

🔄 재현 방법
---

1. 장소를 등록하고 알림을 활성화한다
2. 앱을 홈 버튼으로 빠져나온다 (강제 종료하지 않아도 재현된다)
3. 등록한 장소의 반경 밖에서 안으로 이동한다
4. 도착 시점에 알림도 진동도 발생하지 않음을 확인한다
5. 앱을 실행한다
6. **실행 직후 즉시** 진동과 알림 화면이 뜬다

⚠️ 재현 조건 — 앱을 한동안 사용하지 않아 즉시 실행 쿼터가 소진된 상태에서 더 잘 재현된다. 앱을 자주 켠 직후에는 정상 동작할 수 있어 간헐적으로 보인다.

✅ 예상 동작
---

- 앱을 실행하지 않은 상태에서 등록한 장소에 도착하면 **즉시** 진동과 알림 화면이 뜬다
- 앱을 강제 종료한 상태에서도 발화된다
- 재부팅 후 앱을 한 번도 켜지 않아도 발화된다
- 화면이 꺼진 채 장시간 방치된 뒤에도 발화된다

### 해결 방향

**하이브리드 감시로 전환한다.** 상세는 설계 문서를 따른다.

- 지오펜스를 앱이 직접 등록하고, 앱 소유 리시버가 이벤트를 받아 WorkManager 를 경유하지 않는다
- 이미 상시 실행 중인 감시 서비스가 Flutter 엔진을 상시 보유한다 — 이벤트마다 엔진을 새로 띄우는 구조가 결함의 뿌리이므로 이것이 근본 수정이다
- 장소마다 지오펜스를 둘 등록한다. 근접 반경(정밀 감시 전환용)과 실제 반경(폴백). 정밀 감시가 실패해도 실제 반경 지오펜스로 발화가 보장된다
- 근접 반경에 진입하면 서비스가 위치를 직접 받아 몇 초 안에 판정한다
- 재부팅 복구 리시버를 추가한다

### 지키는 제약

- 판정 로직은 Dart 에 그대로 둔다. 네이티브로 포팅하지 않는다 (규칙 이중화 방지)
- 네이티브에서는 어떤 경우에도 소리를 내지 않는다. 서비스는 진동과 화면 띄우기만 한다
- iOS 는 변경하지 않는다. 이 경로가 없어 해당 결함이 존재하지 않으며, 배포도 서명 자산 만료로 막혀 있다
