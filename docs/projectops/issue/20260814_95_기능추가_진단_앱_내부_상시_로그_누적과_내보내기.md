**문제가 생겨도 추적할 방법이 없다.**

이 앱은 의도적으로 로그를 남기지 않게 만들어져 있다. 두 규칙이 겹친 결과다.

- `docs/04-CONVENTIONS.md` — 릴리스 로그에 위치 좌표 금지, `print` 금지
- 백그라운드 크래시 방어 — 모든 예외를 조용히 삼킨다 (`} on Object { }`)

좌표를 뺀 것은 맞는 판단이었으나 **디버깅 정보까지 통째로 사라졌다.** 현재 예외를 삼키고 아무것도 남기지 않는 지점이 Dart 41곳, Kotlin 14곳이다.

이슈 #93 의 원인(지오펜스 이벤트가 WorkManager 에 갇혀 유실)을 찾을 때도 **로그를 보지 못했다.** 코드를 거꾸로 읽어 추론했을 뿐이다. #93 수정이 실기기에서 동작하지 않으면 같은 방식으로 다시 헤매야 한다.

특히 이 앱은 **백그라운드 동작이 핵심**이라 재현이 어렵다. "어제 도착했는데 안 울렸다"는 상황에서 볼 수 있는 것이 아무것도 없다.

### 로그가 필요한 지점

| 계층 | 남겨야 할 것 |
|---|---|
| 네이티브 리시버 | 지오펜스 브로드캐스트를 받았는가, 어떤 전이인가 |
| 감시 서비스 | 서비스 생명주기, 엔진 부팅 성공/실패, 진동·화면 승격 |
| 정밀 감시 | 위치 측정 수신, 스트림 시작/종료 |
| 판정 | 어떤 장소가 어떤 상태에서 무엇으로 전이했는가, 알림 여부와 그 이유 |
| 등록 동기화 | 몇 개를 등록했는가, 실패했는가 |
| 예외 | 삼키고 있는 55곳 전부 |

🔄 재현 방법
---

1. 백그라운드에서 도착 알림이 오지 않는 상황을 겪는다
2. 원인을 확인하려 한다
3. **볼 수 있는 것이 없다** — 앱 내부에 기록이 남지 않고, 앱은 자기 프로세스의 logcat 도 읽을 수 없다 (Android 4.1+ 제한)

### 요구사항

- **상시 누적** — 앱이 포그라운드든 백그라운드든, 감시 서비스가 도는 동안 계속 기록된다
- **좌표를 포함해 최대한 남긴다** — 로그는 사용자 기기 안에만 있고 전송하지 않는다. 내보내기는 사용자가 직접 하는 행위다
- **설정에서 내보낼 수 있다** — 공유 시트로 파일을 꺼낸다
- **저장공간을 무한히 먹지 않는다** — 상한을 두고 오래된 것부터 버린다

### 설계 방향

**저장은 파일에 append 한다.** Drift 가 아닌 이유는 감시 서비스 엔진이 별도 isolate 이고 Kotlin 계층도 같은 곳에 써야 하기 때문이다. Kotlin 에서 Drift 에 쓰는 것은 복잡하고, `logcat` 은 앱이 자기 로그를 읽을 수 없어 쓸 수 없다.

앱 전용 디렉토리에 두므로 다른 앱이 읽을 수 없다.

**회전은 크기 기준이다.** 상한(5MB 예정)을 넘으면 오래된 절반을 버린다. 대략 2~4주치가 남아, 문제가 생기고 며칠 뒤에 확인해도 추적된다.

**진입점을 새로 만들어야 한다.** 현재 이 앱에는 설정 화면이 없다 — `lib/features` 에 settings 가 없고 라우트에도 없다.

### 규칙 변경이 따라온다

`docs/04-CONVENTIONS.md` 의 "릴리스 로그에 좌표 금지"와 정면으로 충돌한다. 그 규칙의 목적은 로그가 외부로 새는 것을 막는 것이었고, 앱 전용 디렉토리 + 전송 없음 + 사용자 주도 내보내기라면 그 목적이 유지된다.

**문서를 고쳐 예외를 명시한다.** 고치지 않으면 다음 작업자가 규칙 위반으로 보고 지운다.
