🗒️ 설명
---

**등록한 장소에 도착해도 알림이 뜨지 않고 진동만 울린다.** 앱을 직접 열어야 그제서야 알림 화면과 소리가 나온다.

원인은 **백그라운드 발화 경로에 OS 알림을 만드는 주체가 없기 때문**이다. #93 에서 Android 감시 경로를 하이브리드 방식으로 갈아끼우면서, #74 가 만들어둔 알림 발행이 경로에서 통째로 빠졌다.

현재 Android 발화 흐름은 이렇다:

```
GeofenceReceiver → AlertWatchService.handleGeofenceEvent
  → WatchEngineHost._decide()        판정 O · PendingAlert 저장 O
  → beginAlert()
      startVibration()               진동 O
      launchAlertScreen()            오버레이 권한 없으면 조용히 return
```

`GeofenceBackgroundProcessor` 는 진입점마다 알림 발행 여부가 다르다:

| 진입점 | 알림 발행 | 쓰는 곳 |
|---|---|---|
| `handle` | 한다 | iOS |
| `handleTransition` | **안 한다** | Android 감시 서비스 |
| `handlePosition` | **안 한다** | Android 정밀 모드 |

Android 두 경로는 "발화 주체가 네이티브"라는 전제로 알림을 넘기는데, 정작 네이티브 `AlertWatchService` 는 진동과 액티비티 시작만 하고 알림을 만들지 않는다. 그래서 오버레이가 실패하는 순간 **화면에 아무 흔적도 남지 않는다.**

`BackgroundAlertNotifier`(전체화면 인텐트, 알람 카테고리, 스와이프 방지)는 코드에 남아 있지만 iOS 경로에서만 호출된다.

🔄 재현 방법
---

1. 장소를 등록하고 앱을 완전히 종료한다 (프로세스 없음)
2. 등록 반경 안으로 이동한다
3. 진동은 울리지만 상태바에 알림이 없고 화면도 안 뜬다
4. 앱을 직접 실행하면 그때 알림 화면과 소리가 나온다

📸 참고 자료
---

- `android/app/src/main/kotlin/kr/suhsaechan/ear_loc_alert/AlertWatchService.kt` — `beginAlert()`, `launchAlertScreen()`
- `lib/app/background/geofence_background_processor.dart` — 진입점별 알림 발행 표
- `lib/app/background/watch_engine_entrypoint.dart` — "이 경로에서는 알림을 발행하지 않는다" 주석
- `lib/app/background/background_alert_notifier.dart` — 쓰이지 않는 알림 발행부

**오버레이가 안 켜지는 것도 같은 뿌리다.** 두 층이 겹쳐 있다:

1. 오버레이 권한은 시스템 설정으로 나가는 선택 단계라 온보딩에서 놓치기 쉽고, **설정 화면에 권한 항목이 없어 나중에 켤 방법이 앱 안에 없다.** 홈 배너가 유일한 경로다.
2. 권한이 있어도 Android 14+ 는 백그라운드 액티비티 시작을 막는다. 그런데 `launchAlertScreen()` 은 그 실패를 로그 없이 삼켜서 진단 기록에도 원인이 남지 않는다.

✅ 예상 동작
---

- 앱 프로세스가 없어도 도착하는 즉시 **상태바에 알림이 뜬다**
- 화면이 꺼졌거나 잠겨 있으면 알림 화면이 올라온다
- 오버레이 권한이 없어도 알림은 반드시 남는다 (알림이 해제 화면에 닿는 유일한 길)
- 오버레이 승격의 성공, 실패와 그 사유가 진단 기록에 남는다
- 설정 화면에서 알림 관련 권한 상태를 보고 다시 켤 수 있다
- 소리는 여전히 네이티브에서 내지 않는다 (이어폰 판정은 Dart 에만 둔다)
