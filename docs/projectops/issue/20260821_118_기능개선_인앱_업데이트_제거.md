📝 현재 문제점
---

**인앱 업데이트(#104)를 걷어낸다.** Play 스토어로 배포하기로 확정했으므로 앱이 스스로 APK 를 받아 설치할 이유가 없어졌다. 테스터와 사용자는 Play 에서 자동 업데이트를 받는다.

**남겨두면 심사에서 계속 걸린다.** `REQUEST_INSTALL_PACKAGES` 는 Play 가 앱스토어·파일 관리자가 아닌 앱에 거의 허용하지 않는 권한이고, 실제로 비공개 테스트 버전을 올리려 하자 선언을 요구받았다.

```
앱에서 선언되지 않은 android.permission.REQUEST_INSTALL_PACKAGES 을(를) 사용합니다.
핵심 목적: 웹 탐색 / 검색 / 커뮤니케이션 / 파일 공유 / 기기 관리 / 이 중에는 없음
```

위치 알림 앱은 이 중 어느 것도 아니다. **"이 중에는 없음"으로 제출하면 거부된다.**

지금은 `DEV_FLAG` 로 끄기만 한 상태라 코드와 FileProvider 선언이 남아 있다.

🛠️ 해결 방안 / 제안 기능
---

**기능을 통째로 제거한다.** 플래그로 감추는 것과 없는 것은 다르다 — 감춰두면 언젠가 실수로 켜진 채 제출된다. 실제로 이번에 CI Secret 에 `DEV_FLAG=true` 가 남아 심사용 빌드에 권한이 들어갔다.

제거 대상:

| 대상 | 비고 |
|---|---|
| `lib/features/update/` | 전체 |
| `ApkInstaller.kt` | |
| `app_installer` 채널 | `MainActivity` |
| `res/xml/file_paths.xml` | |
| `AndroidManifest.xml` 의 설치 권한·FileProvider | |
| 설정 화면의 "업데이트 확인" 항목 | |
| 관련 테스트 | |

**`DevFlag` 는 남긴다.** 인앱 업데이트가 사라져도 **광고 종류를 가르는 용도**로 여전히 필요하다 — 배포 빌드임이 확인됐을 때만 실제 광고가 나가야 한다 ([10-DECISIONS](../../10-DECISIONS.md) 027, 이슈 #109).

`app_config` 채널의 `isDevBuild` 도 그대로 둔다.

⚙️ 작업 내용
---

- 위 목록 제거
- 설정 화면에서 현재 버전 표시는 유지할지 결정 — 문제를 알릴 때 "몇 버전인가"가 첫 질문이다
- 빌드 산출물에 권한이 없는지 확인

```
aapt2 dump badging <apk> | grep -c REQUEST_INSTALL_PACKAGES   # 0
```
