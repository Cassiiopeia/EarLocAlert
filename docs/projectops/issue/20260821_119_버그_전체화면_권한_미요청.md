🗒️ 설명
---

**온보딩의 신뢰성 권한 단계에서 "전체 화면 알림"만 묻지 않는다.** 배터리 최적화 제외와 다른 앱 위에 표시는 정상적으로 설정 화면이 열리는데, 세 번째만 아무 일도 일어나지 않고 온보딩이 끝난다.

**설정 화면에서는 정상적으로 열린다.** 설정 → 알림 도달 권한 → 전체 화면 알림을 누르면 시스템 설정으로 이동한다. 즉 네이티브 구현과 채널은 멀쩡하고, **연속 요청을 도는 온보딩 루프 쪽 문제다.**

```dart
for (final kind in PermissionGate.reliabilityOrder) {
  if (snapshot.statusOf(kind).isGranted) continue;
  snapshot = await service.request(kind);   // 배터리 → 오버레이 → 전체화면
}
```

후보가 둘이다.

**(1) 요청을 건너뛴다.** `FullScreenIntentChannel.status()` 는 채널 호출이 실패하면 `granted` 를 돌려준다.

```dart
} on Object {
  return PermissionStatus.granted;   // 확인 실패 = 허용으로 간주
}
```

오버레이 설정 화면에서 막 돌아온 순간 채널이 불안정하면 허용으로 읽히고, 루프가 `continue` 로 건너뛴다.

**(2) 설정 화면이 열리다 막힌다.** 앞의 둘과 마지막 하나가 다른 방식이다.

| 권한 | 방식 | 결과를 기다리나 |
|---|---|---|
| 배터리 최적화 | 시스템 다이얼로그 | 예 |
| 다른 앱 위에 표시 | `startActivityForResult` | 예 |
| **전체 화면 알림** | `startActivity` | **아니오** |

마지막만 직접 만든 경로라 결과를 기다리지 않는다. 앱이 아직 백그라운드일 때 호출되면 Android 가 액티비티 시작을 막는다.

🔄 재현 방법
---

1. 앱을 새로 설치하고 온보딩을 진행한다
2. 신뢰성 권한 단계에서 "세 가지 모두 켜기"를 누른다
3. 배터리 최적화 → 다른 앱 위에 표시 설정 화면이 차례로 열린다
4. **전체 화면 알림은 묻지 않고 온보딩이 끝난다**
5. 설정 → 알림 도달 권한에서 "전체 화면 알림"이 미허용으로 남아 있다

✅ 예상 동작
---

- 세 권한을 차례로 묻고, **마지막 하나도 설정 화면이 열린다**
- 확인 실패를 허용으로 간주하지 않는다 — 모르면 물어보는 쪽이 안전하다
- 각 요청의 결과가 동작 기록에 남는다
