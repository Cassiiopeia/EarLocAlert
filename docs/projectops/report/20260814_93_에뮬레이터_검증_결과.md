# 에뮬레이터 검증 결과 — 진입점 결함 발견과 수정

## 요약

**v1.7.0 까지의 코드는 이 이슈를 전혀 고치지 못한 상태였다.** 감시 서비스가 Flutter 엔진을 띄우지 못해 판정이 하나도 돌지 않았다. 에뮬레이터(API 36, Google Play Services)에서 발견해 수정했고, 수정 후 **앱 프로세스가 없는 상태에서 도착 알림이 발화되는 것까지 확인**했다.

## 발견한 결함

### 증상

지오펜스 이벤트는 네이티브까지 정상 도착하는데 판정이 하나도 돌지 않았다.

```
[receiver] 지오펜스 브로드캐스트 수신
[receiver] ENTER 근접=0건 실제=1건 ids=test-place-1 lat=37.5765
(그 뒤로 아무것도 없음 — [engine] 로그 없음)
```

### 원인

```
E flutter : Dart_LookupLibrary: library
  'package:ear_loc_alert/app/background/watch_engine_entrypoint.dart' not found.
E flutter : Could not resolve main entrypoint function.
E flutter : Could not create root isolate.
```

`watch_engine_entrypoint.dart` 를 **Dart 코드 어디에서도 import 하지 않아** 컴파일 번들에서 통째로 빠졌다. Dart 컴파일러는 어떤 진입점에서도 도달할 수 없는 라이브러리를 제외한다.

**`@pragma('vm:entry-point')` 는 함수가 트리셰이킹되는 것만 막는다.** 라이브러리 자체가 포함되지 않는 것은 막지 못한다.

`geofenceBackgroundCallback` 이 동작했던 이유는 `geofence_providers.dart` 가 그 함수를 **값으로 넘겨** 라이브러리가 살아 있었기 때문이다. 새 진입점에는 그런 참조가 없었다.

### 파급

정밀 감시와 폴백(실제 반경 지오펜스) **양쪽 모두 같은 엔진을 쓴다.** 엔진이 안 뜨면 둘 다 죽는다. 폴백을 둔 의미가 없어진 상태였다.

## 수정

진입점을 `main.dart` 로 옮기고 구현에 위임한다. `main.dart` 는 항상 번들에 있다.

```dart
// lib/main.dart
@pragma('vm:entry-point')
void watchEngineMain() => watch_engine.watchEngineMain();
```

`WatchEngine.kt` 의 `ENTRYPOINT_LIBRARY` 를 `package:ear_loc_alert/main.dart` 로 변경했다.

같은 함정을 다시 밟지 않도록 `docs/04-CONVENTIONS.md` 백그라운드 진입점 규약에 기록했다.

## 검증 방법

에뮬레이터 `Medium_Phone_API_36.1` (Google Play Services 포함).

1. APK 설치 후 위치·알림·백그라운드 위치 권한 부여
2. DB 에 테스트 장소 직접 삽입 (37.5765, 126.9780, 반경 200m)
3. 지오펜스 상태를 `outside` 로 미리 확정 — `unknown → inside` 는 무알림이므로(규칙 3) 이걸 안 하면 진입 알림이 안 나간다
4. `adb emu geo fix` 로 위치 이동

## 검증 결과

### 1. 지오펜스 등록 — 장소당 2개

```
[sync] 지오펜스 동기화 완료 등록=1건 ids=test-place-1
[watch] 네이티브 지오펜스 등록 1건 (요청 1건)
[registrar] 지오펜스 등록 성공 2개 (장소 1곳)
```

**"2개 (장소 1곳)"** — 실제 반경 + 근접 반경 폴백 설계가 실증됐다.

### 2. 근접 진입 → 정밀 감시 전환

```
[receiver] ENTER 근접=1건 실제=0건 ids= lat=37.572
[precise] 정밀 감시 시작 대상=1건
```

근접 반경(600m = max(200×3, 500))에 들어가자 정밀 감시가 켜졌다. 하이브리드 구조가 의도대로 동작한다.

### 3. 앱 프로세스 없는 상태에서 발화 — **이 이슈의 핵심**

`adb shell am kill` 로 프로세스를 죽인 뒤 목적지로 이동했다.

```
[receiver] 지오펜스 브로드캐스트 수신
[receiver] ENTER 근접=1건 실제=1건 ids=test-place-1 lat=37.5765
[precise] 정밀 감시 시작 대상=1건
[geofence] OS 전이 수신 place=test-place-1 ENTER
[precise] 위치 측정 lat=37.5765 acc=5.0m
[engine] 알림 발생 place=test-place-1 name=테스트도착지 direction=enter sound=true
[alert] 알림 시작 — 진동 + 화면 승격
[alert] 이미 울리는 중 — 중복 발화 무시
```

**앱이 떠 있지 않은데 도착하니 울렸다.** 이것이 이 이슈가 고치려던 시나리오다.

### 4. 중복 발화 방지

근접·실제 지오펜스가 함께 발화해 두 판정 경로가 모두 알림을 보고했지만, `이미 울리는 중 — 중복 발화 무시` 로 **한 번만 울렸다.**

### 5. Dart·Kotlin 로그 통합 (이슈 #95)

```
[app]      Dart 앱
[sync]     Dart 등록 동기화
[watch]    Kotlin 감시 서비스
[receiver] Kotlin 지오펜스 리시버
[precise]  Kotlin 정밀 감시 + Dart 위치 판정
[engine]   Dart 판정
[alert]    Kotlin 발화
```

한 파일에 시간순으로 섞여 **네이티브가 이벤트를 받았는지 Dart 판정이 돌았는지**를 한눈에 가를 수 있다. 이번 결함을 찾은 것도 이 로그다 — `[receiver]` 는 있는데 `[engine]` 이 없다는 사실이 원인을 곧바로 가리켰다.

### 6. UI 수정 (#97·#98)

- 장소 등록 화면 좌상단에 **뒤로가기 버튼 생성 확인**
- 홈 **왼쪽 아래 내 위치 버튼** 확인
- 상태 바 우측이 **설정 아이콘 하나**로 정리된 것 확인

## 2차 검증 — 재부팅 시나리오에서 결함 하나 더

오버레이 권한을 부여하고 에뮬레이터를 초기화한 뒤 재부팅 시나리오를 확인했다.

### 발견 — 재부팅 후 지오펜스가 복원되지 않았다

```
[watch] 감시 서비스 생성      ← BootReceiver 는 정상 동작
[engine] 감시 엔진 시작
(그 뒤 [receiver] 없음 — 도착해도 이벤트가 오지 않는다)
```

**Android 는 재부팅 시 지오펜스 등록을 잃는다.** `BootReceiver` 가 서비스를 되살려도 등록이 비어 있으면 도착을 감지하지 못한다. 등록은 앱(`MainActivity`)이 켜질 때만 밀어넣는 구조였으므로, **재부팅 뒤 앱을 한 번도 켜지 않으면 알림이 오지 않았다.**

### 수정

감시 엔진이 뜰 때 저장된 장소를 읽어 스스로 등록을 복원한다. 앱이 이미 등록했다면 같은 id 로 덮어써도 결과가 같아 안전하다.

```
[watch] 감시 서비스 생성
[engine] 감시 엔진 시작
[engine] 지오펜스 복원 요청 1건        ← 엔진이 DB 를 읽어 스스로
[watch] 네이티브 지오펜스 등록 1건 (요청 1건)
[registrar] 지오펜스 등록 성공 2개 (장소 1곳)
```

**재부팅 후 앱을 켜지 않았는데 전 과정이 자동으로 돌았다.**

### 덤으로 확인된 것 — 등록 실패가 보인다

초기화된 에뮬레이터에서 위치 서비스가 꺼져 있을 때 이렇게 남았다.

```
[registrar] 지오펜스 등록 실패 com.google.android.gms.common.api.ApiException: 1000
```

`GEOFENCE_NOT_AVAILABLE` 이다. **예전 구조였다면 조용히 실패해 "왜 안 울리지"만 남았을 지점**이다. 위치 모드를 켜자 곧바로 등록에 성공했다.

## 이 검증이 대체하지 못하는 것

에뮬레이터는 실기기가 아니다. 아래는 여전히 미검증이다.

| 항목 | 이유 |
|---|---|
| 제조사 절전(삼성·샤오미)에서 서비스 생존 | 에뮬레이터에는 제조사 절전이 없다 |
| 실제 GPS 정확도에서의 판정 | 모킹 위치는 정확도 5m 로 고정된다 |
| 배터리 소모 | 실사용 패턴이 필요하다 |
| Doze 심층 절전에서의 지연 | 에뮬레이터에서 재현이 어렵다 |
| 오버레이 권한 있을 때 화면 승격 | 이번 검증은 권한 없이 진행됐다 (`오버레이권한=false`) |
| 이어폰 소리 경로 | 에뮬레이터에 오디오 장치가 없다 |
| **재부팅 + 도착의 조합** | 재부팅 후 이 에뮬레이터의 `geo fix` 주입이 먹지 않았다(`last location=null`, 앱을 켜도 동일). 재부팅 전에는 정상 발화했고 재부팅 후 등록 복원도 로그로 확인됐으나, **두 조각을 이어 붙인 전체 흐름은 못 봤다** |

**핵심 경로가 살아 있음은 확인됐고, 환경 의존적인 부분이 남았다.**
