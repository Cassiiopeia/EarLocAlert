# UX 일관성 — 조작 규칙과 용어를 앱 전체에 하나로

> 이슈 #152 · #153

## 문제를 다시 정의한다

처음엔 "디자인 시스템이 없다"고 봤으나 **있다.** `docs/06-UX.md` 183행에 디자인 시스템 절이 있고 거기 이미 `버튼 | 하단, 전체 폭, pill 형태` 가 적혀 있다. 알림음 선택 시트는 **없는 규칙을 어긴 게 아니라 있는 규칙을 어겼다.**

실제 공백은 다른 데 있었다.

| 문서에 있는 것 | 없는 것 |
|---|---|
| 색·타이포·간격·아이콘·금지 목록 | **시트가 언제 확정하는지** |
| 버튼은 하단·전체폭·pill | **무엇이 주 액션인지 판별하는 기준** |
| 지도 다크 스타일 | **같은 기능이 어느 자리에 있는지** |
| — | **용어 사전** |

**"어떻게 생겼나"는 있고 "어떻게 동작하나"가 없다.** 그래서 정적인 것(색·간격·아이콘)은 통일돼 있는데 조작이 화면마다 갈렸다.

### 실측

시트 4개의 확정 방식이 4가지다.

| 시트 | 확정 | 하단 버튼 |
|---|---|---|
| 진동 세기 | 즉시 적용 | 없음 |
| 알림음 크기 | 즉시 적용 | `미리듣기` (보조가 주 자리) |
| 알림 시간대 | 확정 필요 | `저장` + `취소` |
| 알림음 선택 | 확정 필요 | `음원 추가`, 완료는 상단 작은 글씨 |

`sound_picker_sheet.dart` 는 앱에서 **유일하게 `FilledButton` 이 0개**다.

용어는 세 낱말이 비슷한 빈도로 섞여 있다 — `알림음` 57건 · `소리` 64건 · `음원` 64건. 어느 하나가 정식이고 나머지가 예외인 게 아니라 **정해진 적이 없다.**

## 정한 규칙

### 1. 시트 확정 — 성격으로 가른다

> **한 값을 고르는 시트 → 즉시 적용, 하단 확정 버튼 없음**
> **여러 값을 편집하는 시트 → 하단 주 버튼으로 확정**

| 시트 | 성격 | 결과 |
|---|---|---|
| 진동 세기 | 한 값 | 즉시 적용 — **그대로** |
| 알림음 크기 | 한 값(슬라이더) | 즉시 적용 — **그대로**, 미리듣기는 보조 자리로 |
| 알림음 선택 | 한 값 | **즉시 적용으로 바꾼다** — `완료` 제거 |
| 알림 시간대 | 여러 값 | 하단 `저장` — **그대로** |

**이미 맞는 두 화면을 건드리지 않는 것이 이 규칙을 고른 이유다.** "전부 확정 버튼" 이나 "전부 즉시 적용" 은 멀쩡한 화면까지 바꿔야 한다. 그리고 "한 값이냐 여러 값이냐"는 다음에 새 시트를 만들 때 헷갈릴 여지가 없다.

### 2. 주 액션 — 하단은 한 자리, "지금 할 일"만

하단 전체폭 버튼은 **그 화면에서 사용자가 지금 하려는 일** 하나만 차지한다.

| 이 자리에 오는 것 | 오면 안 되는 것 |
|---|---|
| 저장 · 이 위치로 선택 · 알림 끄기 · 계속 | 추가 · 미리듣기 · 내보내기 같은 보조 동작 |

판별 기준: **그 동작을 안 하고 화면을 나가면 사용자의 목적이 달성되지 않는가.** 그렇다면 주 액션이다.

`음원 추가` 는 열 번에 한 번 쓰고, 안 해도 알림음 선택은 끝난다 → 보조다.

### 3. 같은 기능은 같은 자리

| 기능 | 자리 | 방식 |
|---|---|---|
| 내 위치 | 지도 **우하단** | 직접 만든 버튼 (`myLocationButtonEnabled: false`) |

SDK 기본 버튼을 쓰지 않는 이유는 **위치가 오른쪽 위로 고정**이라 검색창·시트와 부딪히기 때문이다. 홈 화면은 #93 에서 이미 직접 만드는 쪽으로 옮겼다. 지도 선택 화면만 남아 있었다.

**이 통일이 #152 의 핀 어긋남을 같이 없앤다.** SDK 버튼을 피하려고 넣었던 `GoogleMap.padding` 이 필요 없어지고, 그 padding 이 카메라 중심을 40px 내려 핀과 어긋나게 한 원인이었다.

### 4. 용어 사전

| 말 | 가리키는 것 | 쓰는 자리 |
|---|---|---|
| **알림음** | 알림이 울릴 때 나는 소리 전체 | 화면 제목, 설정 항목 |
| **기본 알림음** | 앱이 들고 있는 다섯 가지 | 목록 머리말 |
| **내 음원** | 사용자가 등록한 파일 | 목록 머리말, 개수 표시 |
| **소리** | 소리가 나는지 여부(on/off) | 토글 라벨, 설명문 |

`기본 제공` 처럼 **목적어 없는 라벨을 쓰지 않는다.** 무엇이 기본 제공인지 말하지 않으면 아래 `내 음원` 과 짝이 맞지 않는다.

## 규칙을 테스트가 지킨다

**문서는 이미 한 번 어겨졌다.** `버튼 | 하단, 전체 폭` 이 적혀 있는데도 어겼으므로, 새로 적는 것만으로는 같은 일이 또 난다.

이 레포는 이미 답을 쓰고 있다 — `alert_screen_map_test.dart` 가 해제 버튼 크기를 지킨다. 같은 방식으로 규칙을 고정한다.

`test/design_system_test.dart` 가 소스를 읽어 검사한다.

| 검사 | 왜 |
|---|---|
| 한 파일에 하단 `FilledButton` 이 2개 이상이면 실패 | 주 액션이 둘이면 위계가 갈린다 |
| 주 버튼 라벨에 보조 동작 낱말(`추가`·`미리듣기`)이 오면 실패 | 자리를 뺏긴 것 |
| 금지 용어(`기본 제공`)가 있으면 실패 | 용어 사전 위반 |
| `myLocationButtonEnabled: true` 가 있으면 실패 | SDK 버튼 금지 |

**소스를 읽는 테스트인 이유** — 위젯 테스트로는 "앱 전체에 이 패턴이 없다"를 못 센다. 화면마다 테스트를 쓰면 새 화면이 생겼을 때 또 빠진다.

## 하지 않는 것

- **새 디자인 시스템 md 를 따로 만들지 않는다.** `06-UX.md` 가 단일 출처다. 문서가 둘이면 그게 다음 불일치의 씨앗이다
- **l10n 구조를 손대지 않는다.** 문구 27곳이 하드코딩이고 `04-CONVENTIONS.md` 위반이지만, 이번 작업과 섞으면 범위가 두 배가 된다. 별도 이슈로 남긴다
- 색·타이포·간격은 건드리지 않는다. 그쪽은 이미 통일돼 있다
