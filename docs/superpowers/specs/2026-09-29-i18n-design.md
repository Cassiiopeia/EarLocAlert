# 다국어 지원 설계 명세

관련 이슈: #163 (화면 문자열), #164 (네이티브 문자열), #165 (로그 영어), #166 (한국 전제 점검)

## 1. 목표

앱을 한국 밖에서도 쓸 수 있게 한다. 사용자는 **기기 언어를 기본으로** 쓰고, **설정에서 언제든 바꿀 수 있고**, 실수로 읽을 수 없는 언어로 바꿔도 **스스로 되돌릴 수 있어야** 한다.

## 2. 확정된 정책

| 항목 | 결정 |
|---|---|
| 지원 언어 | 한국어(ko), 영어(en), 중국어(zh), 일본어(ja) |
| 기본값 | **기기 설정의 언어.** 지원 목록에 없으면 영어 |
| 앱 안 변경 | 설정에서 바꾼다. 고른 값이 기기 언어보다 우선한다. "기기 설정 따르기"로 되돌린다 |
| 적용 시점 | 앱을 다시 켜지 않아도 즉시 |
| 실수 복구 | 설정의 언어 항목을 **지구본 아이콘 + 고정 위치(설정 화면 맨 아래에 고정, 스크롤 밖)** 로 두고, 선택 목록은 **각 언어의 자기 표기 고정**(한국어, English, 中文, 日本語) |
| 로그 | 앱 언어와 무관하게 **항상 영어** (#165) |

## 3. 기존 명세와 부딪히는 것 — 어떻게 푸는가

이 표가 이번 설계에서 가장 중요하다. 그대로 두면 다국어를 붙이는 순간 깨진다.

| # | 부딪히는 것 | 왜 깨지나 | 해결 |
|---|---|---|---|
| 1 | **결정 037 `String.keepAll`** (`lib/core/text/keep_all.dart`) | 공백이 아닌 **모든 글자 사이**에 줄바꿈 금지 문자(U+2060)를 넣는다. 띄어쓰기가 없는 중국어와 일본어에 쓰면 **줄이 절대 바뀌지 않아 한 줄로 넘친다.** | 한국어일 때만 적용한다. 언어를 모르는 `String` 확장이 아니라 **언어를 아는 함수**로 바꾼다. 중국어와 일본어는 엔진의 기본 줄바꿈(금칙 처리 포함)에 맡긴다. 영어는 낱말 단위라 적용하지 않는다 |
| 2 | **결정 035 `test/design_system_test.dart`** | 소스에서 **한글 리터럴**을 정규식으로 센다(15자 이상 세 낱말, 금지 용어, 주 버튼의 보조 낱말). 문자열이 ARB 로 옮겨지면 소스에서 한글이 사라져 **규칙이 조용히 무력화된다.** | 검사 대상을 **한국어 번역 파일의 값**으로 옮긴다. 금지 용어와 낱말 규칙은 언어별 용어집으로 둔다. 이전 뒤에 규칙이 여전히 잡는지 **일부러 어겨 확인**한다 |
| 3 | **한글 문구를 찾는 위젯 테스트** | `find.text('…')` 를 쓰는 곳이 11개 파일 54곳이다. 언어가 바뀌면 전부 깨진다 | 테스트 앱은 **한국어로 고정**하는 도우미를 쓰고, 문구 대신 번역 키로 찾게 옮긴다. 영어, 중국어, 일본어는 별도 테스트 |
| 4 | **프로젝트 규칙 6: 백그라운드에서 `BuildContext` 금지** vs 문서의 `context.l10n.키` | 백그라운드 알림 문구(`BackgroundAlertNotifier`: 채널 이름, 도착/떠났습니다 문구)는 UI 없이 만들어진다. `context.l10n` 을 못 쓴다 | **컨텍스트 없이 언어만으로 문구를 찾는 경로**를 함께 만든다. 화면은 `context.l10n`, 백그라운드는 저장된 언어를 읽어 같은 번역 파일에서 찾는다. 두 경로가 같은 파일을 쓰므로 문구가 갈리지 않는다 |
| 5 | **백그라운드 isolate 의 저장소 캐시** | 백그라운드 isolate 는 앱과 다른 isolate 라 저장소를 **다시 읽어야** 최신 값을 본다. 안 읽으면 앱에서 바꾼 언어를 모르고 옛 언어로 알림을 만든다 | 백그라운드가 알림 문구를 만들기 직전에 언어를 다시 읽는다(#125 처럼 isolate 경계를 넘는 값은 양쪽에 로그를 남긴다) |
| 6 | **프로젝트 규칙 4: feature 끼리 import 금지** | 언어 설정을 어디에 두는가. 설정 화면(feature)이 언어를 바꾸고, 앱 전체(`MaterialApp`)와 다른 feature 의 화면이 그것을 읽는다 | 언어 값과 번역은 **`core`** 에 둔다(공용). 설정 feature 는 `core` 의 값을 바꾸기만 하고, `app` 계층이 `MaterialApp` 에 주입한다. feature 끼리는 서로를 모른다 |
| 7 | **규칙 5: `@riverpod` 코드 생성만 쓴다** | 언어 상태도 예외 없이 같은 방식 | 언어 상태는 `@riverpod` 로 만든다 |
| 8 | **`docs/01-REQUIREMENTS.md` F5, `docs/09-RELEASE.md`** | 다국어를 "한국어, 영어" 로 적고 Phase 2 로 미뤘다 | 4개 언어로 갱신하고 우선순위를 올린다 |
| 9 | **`CLAUDE.md`, `docs/04-CONVENTIONS.md` "l10n 을 거친다"** | 실제 코드에는 l10n 이 없다. 문서와 코드가 어긋나 있다 | 구현 후 사실에 맞게 갱신한다 |
| 10 | **`docs/06-UX.md` 용어 통일(#153)** | 용어 통일 규칙이 한국어 낱말로만 적혀 있다 | 언어별 용어집을 만든다(같은 동작은 같은 낱말) |
| 11 | **`docs/10-DECISIONS.md` 주소 검색(카카오)** | 카카오는 해외 검색이 안 된다. 일본, 중국 사용자에게 맞지 않는다 | #166 에서 제공자를 다시 정한다 |

## 4. 추가로 정해야 하는 것 (권장안 포함)

| # | 정할 것 | 권장 | 이유 |
|---|---|---|---|
| A | **중국어 표기**: 간체(zh-Hans)와 번체(zh-Hant) | 간체로 시작한다. 번체 기기(대만, 홍콩)는 **영어로** 보이게 둔다. 번체는 후속 | 잘못된 자형은 오독으로 이어진다. 번체를 간체로 보이게 하지 않는다 |
| B | **언어 저장 위치** | 앱과 네이티브가 함께 읽는 저장소(SharedPreferences). 값은 `system`, `ko`, `en`, `zh`, `ja` | 알림은 앱이 죽어 있어도 Kotlin 이 만든다. Kotlin 이 읽을 수 있어야 한다. 이 키 이름은 **양쪽의 계약**이라 문서에 못 박는다 |
| C | **Android 13+ 의 OS 앱별 언어 기능과의 관계** | **선언하지 않고 앱 안 설정만 단일 출처로 둔다** | OS 설정에서 앱 언어를 바꾸는 화면이 생기면 앱 설정과 **두 곳에서 어긋난다.** 둘을 동기화하는 비용이 이익보다 크다 |
| D | **울리는 중에 언어를 바꾸면** | 진행 중인 알림 세션은 영향받지 않는다. 다음 알림부터 새 언어 | 알림 해제 경로(핵심 가치)를 건드리지 않는다 |
| E | **iOS 권한 안내 문구** | OS 가 기기 언어로 고른다. 앱 안 언어와 어긋날 수 있다는 **한계를 명시한다** | 앱 안에서 바꿀 수 없다 |
| F | **지도 라벨 언어** | 지도 SDK 는 기기 언어를 따른다. 앱 언어와 어긋나도 **허용한다** (확인 필요) | 앱 언어로 강제할 수단이 있는지 검증 후 결정 |
| G | **일본어, 중국어 글꼴** | 번들하지 않고 시스템 글꼴로 대체한다. 굵기와 자형이 어긋나는지 화면으로 확인한다 | 글꼴 하나가 수 MB 라 번들 6MB 가 크게 는다 |
| H | **날짜, 시간, 숫자 표기** | 시각은 **기기의 24시간/12시간 설정**을 따르고, 요일 이름과 숫자 형식은 **앱 언어**를 따른다 | 사용자는 시계 형식을 기기에서 이미 정했다 |
| I | **복수형, 조사, 어순** | 번역 파일의 메시지 문법(복수형 규칙)을 쓴다. 문자열을 이어 붙이지 않는다 | 언어마다 어순과 복수 규칙이 다르다 |
| J | **원문 언어와 누락 처리** | 원문은 한국어로 쓰고 나머지를 번역한다. **키가 하나라도 빠지면 테스트가 실패**한다. 실행 중 빠진 키는 영어로 채운다 | 누락을 사용자가 발견하게 두지 않는다 |

| L | **알림음 프리셋 이름** | 저장은 식별자(`preset:siren`)로, 표시 이름은 번역 | 이미 식별자로 저장돼 있어 이름만 옮기면 된다 |
| M | **스크린리더 발음** | 화면 문구에 언어 표시를 붙인다. 앱 언어와 기기 음성 언어가 다르면 발음이 어긋날 수 있음을 인지한다 | 접근성 |
| N | **번역 품질** | 기계 번역 초안 뒤 원어민 검수. 검수 전에는 영어를 우선 배포한다 | 잘못된 번역은 권한 안내와 알림에서 신뢰를 깎는다 |

## 5. 구조 (요약)

- **번역 파일**: `core` 아래에 4개 언어 파일을 둔다. 한국어가 원문이다.
- **화면**: `context.l10n.키` 로 읽는다(문서가 이미 약속한 방식).
- **백그라운드, 네이티브 경로**: 저장된 언어를 읽어 같은 파일 또는 같은 뜻의 네이티브 리소스에서 찾는다.
- **언어 상태**: `core` 의 `@riverpod` 상태 하나. 값이 `system` 이면 기기 언어를 따르고 지원하지 않으면 영어. `app` 계층이 `MaterialApp` 의 언어로 넘긴다.
- **줄바꿈**: 한국어에만 낱말 단위 보호를 적용한다.

## 6. 테스트

- 번역 키가 네 언어에서 서로 빠짐없이 같은지 확인한다.
- 소스에 화면용 한글 리터럴이 새로 생기면 실패한다(로그 제외).
- 네 언어로 주요 화면(알림 화면의 84px 해제 버튼, 상태 알약, 두 줄 장소명 + 지도 카드)이 **넘치지 않는지** 본다. 글자 1.3배와 함께.
- **읽을 수 없는 언어로 바꾼 뒤 되돌릴 수 있는지**를 네 언어 각각에서 확인한다.
- 앱에서 고른 언어가 백그라운드 알림 문구에 반영되는지 확인한다(isolate 경계 양쪽 로그).
- 기존 위젯 테스트는 한국어로 고정해 통과하는 상태를 먼저 만든다.

## 7. 진행 순서

1. 이 명세의 §3, §4 를 확정한다(특히 A, B, C).
2. 기반: 번역 파일, 언어 상태, 컨텍스트 없는 조회 경로, 한국어 전용 줄바꿈. **기존 테스트가 한국어로 고정된 채 통과**하는 것까지.
3. 화면별 문자열 이전을 나눠 진행한다(화면마다 테스트와 넘침 확인).
4. 네이티브(#164), 로그(#165)는 병행 가능. 로그는 다른 것과 독립이라 먼저 끝내도 된다.
5. #166 의 광고 동의 사실 확인은 이 작업과 무관하게 **가장 먼저** 한다(심사와 계정에 직결).
